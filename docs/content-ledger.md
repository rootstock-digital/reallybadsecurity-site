# RBS content ledger

**Status:** repository-only working ledger. It does not publish content or authorize changes to application code, external platforms, Shopify, newsletter settings, redirects, analytics, or deployments.

## How to use this ledger

Use one row for every idea, existing external item, local draft, migration candidate, and campaign context page. Keep IDs stable. Do not replace an original source URL, canonical decision, or approval note without recording why.

### Controlled values

- **Editorial lane:** `Really Bad Security`, `Really Bad Internet`, `Really Bad Goods`.
- **Format:** `note`, `explainer`, `commentary`, `video-companion`, `series`, `campaign`, `product-context`, `source-inventory`, or `integration-placeholder`.
- **Status:** `idea`, `draft`, `in_review`, `approved-to-publish`, `published`, `migration-review`, `archived`, or `blocked`.
- **Canonical / redirect:** `local-canonical`, `external-canonical`, `rewrite-before-migrate`, `no-local-page`, `decision-needed`, or `not-applicable`.
- **SEO readiness:** `not-started`, `drafted`, `reviewed`, or `not-applicable`.
- **Priority:** `P0`, `P1`, `P2`, or `P3`.

## One-person operating guide

1. **Capture:** add a row when a social post, video, observation, or external item has possible durable value. Start at `idea`, `migration-review`, or `blocked`; do not create a site page yet.
2. **Qualify:** choose one lane, one format, one primary topic, and a stable ID. Record the original URL and whether a local page is justified.
3. **Prepare:** set sources, owner/byline, accessibility/media needs, SEO readiness, companions, and Goods relevance. Mark factual content `in_review` only when sources and scope are ready.
4. **Approve:** record the owner decision in the final column. Only an entry marked `approved-to-publish` may become a local production page.
5. **Publish and maintain:** record the local URL and dates, preserve the canonical decision, add update/correction notes, and revisit social/video/newsletter/Goods links when their source changes.
6. **Migrate carefully:** external content remains external-canonical until rights, rewrite scope, and canonical behavior are explicitly decided. Never bulk-copy or bulk-redirect from the ledger.

## Maintenance rules

- Keep unknowns as `unknown`, `blocked`, or `decision needed`; do not fill them with plausible guesses.
- Use one row per external article/video/episode only after its title, owner, and URL are individually verified.
- Keep sensitive facts, credentials, customer data, Shopify tokens, and private analytics out of the ledger.
- Review `P0` rows before adding new content or integrations to the redesigned site.
